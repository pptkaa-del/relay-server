# Relay Control — сервер управления релейными платами

Сервер для релейных блоков на ESP8266 + SIM800L: MQTT-брокер, база данных, веб-панель и обработчик сообщений.
Разворачивается одной командой на чистом Ubuntu/Debian.

| Компонент | Назначение |
|---|---|
| **Mosquitto** (порт 1883, по желанию 8883/TLS) | брокер: вход только по паролю, каждая плата видит только свой `com/{id}` |
| **MariaDB** | состояния плат и реле, команды, журнал событий, журнал MQTT-сообщений |
| **Apache + PHP** | веб-панель: устройства, страница платы, MQTT-монитор |
| **relay-mqtt-subscriber** | служба systemd: принимает `stat`/`rep`, следит за связью, подключается к сторонним брокерам |
| `firmware/` | прошивки (Arduino IDE): ESP8266 + SIM800L (основная и без PIN), плата OFFON ver_5_1 — ESP32 + SIM7670 и ATtiny85 |

## Установка

Поддерживаются Ubuntu 22.04 / 24.04 / 26.04 и Debian 12 / 13. Нужен root.

```bash
sudo apt-get update && sudo apt-get install -y git
```

```bash
sudo git clone https://github.com/pptkaa-del/relay-server.git /opt/relay-server
```

```bash
sudo bash /opt/relay-server/install.sh
```

Если репозиторий приватный, `git clone` попросит логин GitHub и [персональный токен](https://github.com/settings/tokens)
вместо пароля. Если репозиторий публичный, можно установить одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/relay-server/main/bootstrap.sh | sudo bash
```

Установка проходит без вопросов. В конце скрипт выводит адрес панели, логин `admin` и сгенерированный пароль.
Все пароли сохраняются в `/root/relay-server-credentials.txt`.

Полезные параметры (`install.sh --help` выводит полный список):

```bash
sudo bash /opt/relay-server/install.sh --admin-pass 'МойПароль' --devices "1 2 3"
sudo bash /opt/relay-server/install.sh --domain relay.example.ru --email admin@example.ru   # HTTPS + MQTT TLS 8883
sudo bash /opt/relay-server/install.sh --replace-xampp       # отключить старую установку на XAMPP
```

### Обновление

```bash
sudo relay-update
```

Команда выполняет `git pull` и запускает установку повторно. Пароли, пользователи, платы и журналы сохраняются,
а схема БД обновляется автоматически.

## Работа с платами

Адрес сервера задаётся в **меню настройки платы** (прошивка v2.3+): подключите плату по USB, откройте монитор порта
(115200), в первые 5 секунд после включения отправьте `i`, введите пароль меню и выберите:

| Пункт | Настройка |
|---|---|
| 1 | ID платы (целое число без ведущих нулей — по нему вычисляются логин и пароль MQTT) |
| 2 | PIN SIM-карты |
| 3 | сброс глобального счётчика ошибок PIN |
| 4 | номер реле контроля питания шкафа (1–4) |
| **5** | **адрес сервера MQTT** — домен или IP этого сервера |
| **6** | **порт** (по умолчанию 1883) |
| **7** | **APN оператора** (`-` — по умолчанию SIM-карты) |
| **8** | **сброс к заводским настройкам**: полная очистка EEPROM, запись начальных параметров из прошивки и перезагрузка (подтверждение — дважды `RESET`) |
| 9 | выход с сохранением |

По умолчанию (и после обновления со старой прошивки) адрес — `185.209.29.25:1883`; ID и PIN при обновлении сохраняются.

**Начальные параметры в прошивке.** В начале файла прошивки есть блок «ЗАВОДСКИЕ НАСТРОЙКИ»:
`DEFAULT_DEVICE_ID`, `DEFAULT_SIM_PIN`, `DEFAULT_ALARM_RELAY`, `DEFAULT_SERVER_HOST`, `DEFAULT_SERVER_PORT`, `DEFAULT_APN`.
С этими значениями плата стартует впервые (чистая EEPROM) и после сброса к заводским настройкам (пункт 8).
Задав их перед прошивкой, можно не вводить параметры через меню. Неверное значение (например, реле 5) не даст собрать прошивку.

`APPLY_DEFAULTS_ON_FLASH`:
* `0` (по умолчанию) — при перепрошивке уже настроенной платы её настройки сохраняются (обычное обновление);
* `1` — после прошивки этой сборки плата один раз применит начальные параметры, даже если уже была настроена
  (удобно при выпуске: задать `DEFAULT_DEVICE_ID` и прошить). Перезагрузки их больше не трогают.

**Вариант без PIN SIM-карты** — `firmware/Relay_MQTT_v2_akb_nopin`: для SIM-карт с отключённым запросом PIN.
Пунктов меню 2 и 3 в нём нет, остальные номера те же. Если вставить SIM с включённым PIN, плата напишет об этом
в мониторе порта и перезагрузится. Между вариантами можно переходить в обе стороны — ID, адрес сервера и APN сохраняются.
Если плата не подключается, в мониторе порта будет строка `MQTT connect failed, state=…` с расшифровкой причины.

Каждую плату нужно зарегистрировать в брокере. Проще всего кнопкой **«Добавить плату»** на главной странице панели:
ID (из меню настройки платы, пункт 1), название, адрес и подписи реле. То же самое из консоли:

```bash
sudo relay-device add 12 "Шкаф ТП-12" "ул. Ленина, 14"
```

Кнопка в панели выполняет то же самое с правами root без прямого доступа веб-сервера к ним: панель кладёт запрос
в `/var/lib/relay-server/queue`, а служба systemd `relay-device-queue` (от root) сразу его обрабатывает через
обёртку `relay-device-web`, которая пропускает только `add`/`del` с проверенным ID. Запасной путь — `sudo`
с правилом только на эту обёртку (`/etc/sudoers.d/relay-server`, совместимо с sudo-rs). Удаление платы на её странице
(«Изменить» → «Удалить плату») закрывает ей доступ к брокеру.

| Команда | Действие |
|---|---|
| `relay-device add <ID> [название] [адрес]` | добавить плату (логин и пароль MQTT вычисляются из ID, как в прошивке) |
| `relay-device del <ID>` | закрыть плате доступ к брокеру |
| `relay-device list` | список плат и их статус |
| `relay-device pass <ID>` | показать MQTT-логин и пароль платы |
| `relay-device user-add <логин> [пароль]` | добавить пользователя панели или сменить пароль |
| `relay-device user-del <логин>` | удалить пользователя панели |

## Веб-панель

**Устройства** (`/`). Сводка: всего, на связи, нет связи, на АКБ, ожидают. Плитки работают как фильтры.
На карточке платы видно, когда пришли последние данные, уровень сигнала GSM и переключатели реле с вашими подписями.
Там же кнопки «Запросить статус» и «Перезагрузить плату». Есть поиск и сортировка.

**Плата** (`/device.php?id=N`):
* «Последнее поступление данных»: когда, какой топик, расшифровка и HEX, число сообщений за час и сутки;
* управление каждым реле (вкл / выкл / перезапуск) и всеми сразу, перезагрузка платы;
* журналы по устройству с фильтром по датам и выгрузкой в CSV:
  * **События**: связь появилась или пропала, изменения реле, авария АКБ, команды (кто отправил) и ответы платы;
  * **MQTT-сообщения**: все пакеты платы;
  * **Команды**: история и статусы;
* редактирование названия, адреса, координат и подписей реле.

**Монитор** (`/monitor.php`):
* живая лента MQTT-сообщений выбранного брокера с расшифровкой `stat`/`rep`/`com`, фильтром по плате и топику;
* отправка команд (включая перезагрузку) и произвольных сообщений (текст или HEX);
* **подключение к другим брокерам**: кнопка «Брокеры…» → «Добавить брокер» (адрес, порт, логин, пароль, TLS, подписки).
  Подписки указываются через запятую: `#` (всё) или, например, `stat, rep, com/#`. Знак `#` ставится только
  отдельно или в конце фильтра: на фильтр вроде `#stat` брокер разрывает соединение, поэтому панель его не примет.
  «Проверить подключение» проверяет и логин, и подписки.
  Сервер держит постоянное соединение со всеми включёнными брокерами и сохраняет их сообщения в журнал.
  На стороннем брокере видны его платы (по последним `stat`), и им можно отправлять команды.
  Так удобно переводить платы со старого сервера: подключите его брокер и наблюдайте за платами из новой панели.

Панель адаптирована под телефон: на узком экране меню переезжает вниз, журнал сообщений выводится карточками.
Есть светлая и тёмная тема. Прежняя панель доступна по адресу `/legacy.php`.

## Плата OFFON reley ver_5_1 (ESP32 + SIM7670)

Для новой платы — прошивки `firmware/OFFON_v5_esp32` (ESP32) и `firmware/OFFON_v5_watchdog_attiny85`
(внешний сторожевой таймер). Карта выводов и замечания по разводке — `docs/OFFON_v5_board.md`.
Меню настройки, заводские параметры и протокол те же, что у прошивки v2.3; дополнительно плата передаёт
состояние **замка** и **двери (геркон)** — в панели на странице платы появляется блок «Замок и дверь»
с кнопками «Открыть замок», «Подать питание», «Снять питание», а в журнале — события двери.

## Напряжение АКБ

Прошивка v2.2 передаёт в `stat` значение АЦП входа АКБ, а сервер пересчитывает его в вольты по двум точкам калибровки
каждой платы: **АЦП при 19 В** и **АЦП при 26 В**. Их можно указать сразу в форме «Добавить плату» или позже —
«Изменить» на странице платы. Порядок калибровки:

1. Подайте на вход АКБ платы 19 В от лабораторного источника.
2. На странице платы нажмите «Запросить статус», затем «Изменить» → «Текущее» у поля «АЦП при 19 В».
3. Повторите для 26 В и сохраните.

Напряжение показывается на карточке платы, на её странице (шкала 19–26 В и график за 24 ч / 7 дней) и в журнале сообщений.

## Незарегистрированные платы

Если плата с прошивкой пытается подключиться к брокеру, но ещё не добавлена на сервер, брокер её не пускает,
а панель показывает её на главной странице в блоке **«Обнаружены незарегистрированные платы»** (ID, число попыток, IP).
Кнопка «Добавить» открывает форму с уже заполненным ID. Платы, которые видны на стороннем брокере в мониторе,
но отсутствуют на этом сервере, отмечены кнопкой «+ Добавить в систему».

## Наклейки с серийным номером

Раздел **«Наклейки»** (`/labels.php`) собирает картинку наклейки из шаблона `web/assets/label/label_template.png`,
меняя только строку «SN: …» (шрифт Carlito — метрический аналог Calibri, лицензия SIL OFL, лежит рядом).

* серийный номер вручную или кнопкой «Следующий» (последний выпущенный +1);
* серия: «Количество» — номера подряд с сохранением длины (…059, …060, …061);
* «Скачать PNG» (1942×833 px) и «Печать» — лист наклеек заданной ширины в мм (по умолчанию 70 × 30 мм);
* журнал выпущенных номеров: повтор номера подсвечивается и требует подтверждения, поиск по номеру и примечанию.

Чтобы сменить оформление, замените `label_template.png` картинкой того же размера с пустым местом под номер;
если место другое — поправьте константы `SN_X`, `SN_BASELINE`, `SN_FONT_PX` в `web/assets/labels.js`.

## Обслуживание

```bash
journalctl -u relay-mqtt-subscriber -f          # обработка сообщений и подключения к брокерам
tail -f /var/log/mosquitto/mosquitto.log         # подключения плат
systemctl restart relay-mqtt-subscriber mosquitto
```

Расположение файлов: панель — `/var/www/relay`, настройки — `/etc/relay-server/`,
брокер — `/etc/mosquitto/conf.d/relay-server.conf`, ACL — `/etc/mosquitto/relay.acl`.

## Перенос данных со старого сервера (XAMPP)

```bash
/opt/lampp/bin/mysqldump -u root u2702672_service_reley_v1 > old.sql     # на старом сервере
```

```bash
sudo mysql u2702672_service_reley_v1 < old.sql && sudo bash /opt/relay-server/install.sh   # на новом
```

После переноса выполните `sudo relay-device add <ID>` для каждой платы.

```
sql/schema.sql        схема и миграции БД

```
