# Relay Control — сервер управления релейными платами

Сервер для релейных блоков на ESP8266 + SIM800L: MQTT-брокер, база данных, веб-панель и обработчик сообщений.
Разворачивается одной командой на чистом Ubuntu/Debian.

| Компонент | Назначение |
|---|---|
| **Mosquitto** (порт 1883, по желанию 8883/TLS) | брокер: вход только по паролю, каждая плата видит только свой `com/{id}` |
| **MariaDB** | состояния плат и реле, команды, журнал событий, журнал MQTT-сообщений |
| **Apache + PHP** | веб-панель: устройства, страница платы, MQTT-монитор |
| **relay-mqtt-subscriber** | служба systemd: принимает `stat`/`rep`, следит за связью, подключается к сторонним брокерам |
| `firmware/` | прошивка платы (Arduino IDE), с командой 5 «перезагрузка» |

## Установка

Поддерживаются Ubuntu 22.04 / 24.04 / 26.04 и Debian 12 / 13. Нужен root.

```bash
sudo apt-get update && sudo apt-get install -y git
```

```bash
sudo git clone https://github.com/pptkaa-del/relay-server.git /opt/relay-server
```

```bash
sudo bash /opt/relay-server/install.sh
```

Если репозиторий приватный, `git clone` попросит логин GitHub и [персональный токен](https://github.com/settings/tokens)
вместо пароля. Если репозиторий публичный, можно установить одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/relay-server/main/bootstrap.sh | sudo bash
```

Установка проходит без вопросов. В конце скрипт выводит адрес панели, логин `admin` и сгенерированный пароль.
Все пароли сохраняются в `/root/relay-server-credentials.txt`.

Полезные параметры (`install.sh --help` выводит полный список):

```bash
sudo bash /opt/relay-server/install.sh --admin-pass 'МойПароль' --devices "1 2 3"
sudo bash /opt/relay-server/install.sh --domain relay.example.ru --email admin@example.ru   # HTTPS + MQTT TLS 8883
sudo bash /opt/relay-server/install.sh --replace-xampp       # отключить старую установку на XAMPP
```

### Обновление

```bash
sudo relay-update
```

Команда выполняет `git pull` и запускает установку повторно. Пароли, пользователи, платы и журналы сохраняются,
а схема БД обновляется автоматически.

## Работа с платами

Прошивка подключается к адресу из `mqtt.setServer(...)` в `firmware/Relay_MQTT_v2_akb/Relay_MQTT_v2_akb.ino`
(сейчас `185.209.29.25:1883`). Если сервер работает на другом адресе, исправьте его и перепрошейте плату
(подробнее — в `docs/ИНСТРУКЦИЯ ПО НАСТРОЙКЕ РЕЛЕЙНОГО БЛОКА.docx`).

Каждую плату нужно зарегистрировать в брокере:

```bash
sudo relay-device add 12 "Шкаф ТП-12" "ул. Ленина, 14"
```

| Команда | Действие |
|---|---|
| `relay-device add <ID> [название] [адрес]` | добавить плату (логин и пароль MQTT вычисляются из ID, как в прошивке) |
| `relay-device del <ID>` | закрыть плате доступ к брокеру |
| `relay-device list` | список плат и их статус |
| `relay-device pass <ID>` | показать MQTT-логин и пароль платы |
| `relay-device user-add <логин> [пароль]` | добавить пользователя панели или сменить пароль |
| `relay-device user-del <логин>` | удалить пользователя панели |

## Веб-панель

**Устройства** (`/`). Сводка: всего, на связи, нет связи, на АКБ, ожидают. Плитки работают как фильтры.
На карточке платы видно, когда пришли последние данные, уровень сигнала GSM и переключатели реле с вашими подписями.
Там же кнопки «Запросить статус» и «Перезагрузить плату». Есть поиск и сортировка.

**Плата** (`/device.php?id=N`):
* «Последнее поступление данных»: когда, какой топик, расшифровка и HEX, число сообщений за час и сутки;
* управление каждым реле (вкл / выкл / перезапуск) и всеми сразу, перезагрузка платы;
* журналы по устройству с фильтром по датам и выгрузкой в CSV:
  * **События**: связь появилась или пропала, изменения реле, авария АКБ, команды (кто отправил) и ответы платы;
  * **MQTT-сообщения**: все пакеты платы;
  * **Команды**: история и статусы;
* редактирование названия, адреса, координат и подписей реле.

**Монитор** (`/monitor.php`):
* живая лента MQTT-сообщений выбранного брокера с расшифровкой `stat`/`rep`/`com`, фильтром по плате и топику;
* отправка команд (включая перезагрузку) и произвольных сообщений (текст или HEX);
* **подключение к другим брокерам**: кнопка «Брокеры…» → «Добавить брокер» (адрес, порт, логин, пароль, TLS, подписки).
  Сервер держит постоянное соединение со всеми включёнными брокерами и сохраняет их сообщения в журнал.
  На стороннем брокере видны его платы (по последним `stat`), и им можно отправлять команды.
  Так удобно переводить платы со старого сервера: подключите его брокер и наблюдайте за платами из новой панели.

Панель адаптирована под телефон: на узком экране меню переезжает вниз, журнал сообщений выводится карточками.
Есть светлая и тёмная тема. Прежняя панель доступна по адресу `/legacy.php`.

## Хранение журналов

| Журнал | Таблица | Срок | Параметр установки |
|---|---|---|---|
| MQTT-сообщения | `mqtt_messages` | 14 дней | `--retention` |
| События плат | `device_events` | 180 дней | `--events-retention` |
| Команды | `commands` | бессрочно | — |

## Обслуживание

```bash
journalctl -u relay-mqtt-subscriber -f          # обработка сообщений и подключения к брокерам
tail -f /var/log/mosquitto/mosquitto.log         # подключения плат
systemctl restart relay-mqtt-subscriber mosquitto
```

Расположение файлов: панель — `/var/www/relay`, настройки — `/etc/relay-server/`,
брокер — `/etc/mosquitto/conf.d/relay-server.conf`, ACL — `/etc/mosquitto/relay.acl`.

## Перенос данных со старого сервера (XAMPP)

```bash
/opt/lampp/bin/mysqldump -u root u2702672_service_reley_v1 > old.sql     # на старом сервере
```

```bash
sudo mysql u2702672_service_reley_v1 < old.sql && sudo bash /opt/relay-server/install.sh   # на новом
```

После переноса выполните `sudo relay-device add <ID>` для каждой платы.

## Структура репозитория

```
install.sh            установка и обновление (идемпотентно)
bootstrap.sh          установка одной командой через curl
bin/relay-device      управление платами и пользователями
bin/relay-update      git pull + install.sh
sql/schema.sql        схема и миграции БД
systemd/              служба MQTT-подписчика
web/                  веб-панель и подписчик (PHP 8.1+, библиотека php-mqtt в web/vendor)
firmware/             прошивка платы
docs/                 протокол (PROTOCOL.md) и исходные инструкции
```
