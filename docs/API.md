# API off-on service для сторонних систем

Версия API: **v1**. Через API сторонняя система (CRM, диспетчерская, SCADA, бот) получает данные устройств
и, если разрешено, управляет реле.

## Доступ

**Ключ API** выдаёт администратор: панель → «Пользователи» → «Пользователи API» → «Добавить пользователя API».
Для каждого пользователя API задаются:

| Настройка | Значение |
|---|---|
| Имя | латиница, цифры, `_ . -` — так пользователь API подписан в журнале устройства: `api:имя` |
| Права | «Только чтение» или «Чтение и управление» |
| Устройства | `*` — все (и добавленные позже) или список номеров: `1, 3, 5-10` |
| Разрешённые IP-адреса | пусто — с любых адресов, иначе только с перечисленных |
| Запросов в минуту | ограничение частоты (по умолчанию 120) |

Ключ показывается **один раз** при создании. Сервер хранит только его отпечаток (SHA-256): если ключ утерян,
выдайте новый кнопкой «Новый ключ» — старый сразу перестанет работать. Отключить доступ без удаления —
«Изменить» → «Доступ: отключён».

**Адрес API:** `https://<сервер>/api/v1/` (тот же адрес, что у панели). Используйте HTTPS: ключ передаётся
в каждом запросе.

**Ключ передаётся в заголовке** (любой из двух):

```
Authorization: Bearer ofs_0123456789abcdef…
X-API-Key: ofs_0123456789abcdef…
```

В адресе (`?key=`) ключ не принимается — адреса попадают в журналы серверов.

## Общие правила

* Ответы — JSON в UTF-8. Время — ISO 8601 с часовым поясом сервера: `2026-11-12T14:35:37+03:00`.
* Параметры `GET` — в адресе; `POST` — формой (`application/x-www-form-urlencoded`) или JSON (`Content-Type: application/json`).
* Пользователь API видит только выданные ему устройства. Чужое или несуществующее устройство — `404`.
* Ошибка: HTTP-код и `{"error": "текст", "code": "код"}`.

| HTTP | code | Причина |
|---|---|---|
| 400 | `bad_command`, `bad_relay`, `bad_ids`, `bad_json`, … | неверные параметры |
| 401 | `no_key`, `bad_key` | нет ключа, ключ неверный или отключён |
| 403 | `read_only`, `ip_denied` | ключ только для чтения; запрос с неразрешённого IP; реле не выдано |
| 404 | `not_found` | устройство или команда не найдены (или нет доступа) |
| 405 | `method` | неверный метод (GET / POST) |
| 409 | `not_allowed`, `send_failed` | реле отключено в настройках / омывание; устройство ещё не выходило на связь; ошибка MQTT |
| 429 | `rate_limit` | превышено число запросов в минуту (заголовок `Retry-After` — через сколько секунд повторить) |

Заголовки `X-RateLimit-Limit` и `X-RateLimit-Remaining` в каждом ответе — ограничение и остаток на текущую минуту.

## Устройство

Устройство в ответах API:

```json
{
  "id": 12,
  "name": "Шкаф ТП-12",
  "address": "ул. Ленина, 14",
  "owner": "ООО «Ромашка»",
  "sim_phone": "+79997777777",
  "coordinates": {"lat": 55.7558, "lon": 37.6173},
  "mount": "mounted",
  "mount_changed_at": "2026-11-01T10:00:00+03:00",
  "online": true,
  "state": "online",
  "last_data_at": "2026-11-12T14:35:37+03:00",
  "version": 2,
  "signal": 18,
  "battery": {"voltage": 25.4, "type": 24, "adc": 812, "low": false, "at": "2026-11-12T14:35:37+03:00"},
  "all_off": false,
  "door_open": null,
  "break_in": null,
  "lock": null,
  "relays": [
    {"num": 1, "name": "Гор Свет", "mode": "normal", "state": "off", "power": false,
     "changed_at": "2026-11-12T14:35:37+03:00", "control": true},
    {"num": 2, "name": "Модем", "mode": "normal", "state": "on", "power": true,
     "changed_at": "2026-11-12T14:35:37+03:00", "control": true}
  ]
}
```

| Поле | Значение |
|---|---|
| `coordinates` | координаты или `null`, если не заданы |
| `mount` | `mounted` — смонтировано, `not_mounted` — не смонтировано, `repair` — демонтировано (в ремонт) |
| `online` | данные от устройства приходили за последние 350 с |
| `state` | `online` — на связи; `offline` — нет связи; `never` — ещё не выходило на связь; `power_off` — отключено по питанию (связь пропала при АКБ ниже 20 В для 24 В / 10 В для 12 В); `error` — устройство сообщило об ошибке; `not_mounted`, `repair` — не смонтировано / в ремонте и не на связи (отсутствие данных у них не неисправность) |
| `version` | версия устройства: 1, 11 («1-1»), 2, 3 (плата ver_5_1) или `null` |
| `signal` | уровень сигнала GSM 0–31 (99 — нет данных) или `null` |
| `battery` | АКБ: напряжение (В, `null` — не откалибровано), тип 12/24 В, значение АЦП, `low` — ниже 6 В. `null` — контроль АКБ выключен |
| `all_off` | на связи, но ни на одно реле не подаётся питание |
| `door_open` | дверь открыта (`true` / `false`) — если реле 4 управляет замком или у платы ver_5_1 есть датчик двери; иначе `null` |
| `break_in` | тревога «взлом двери»: `{"at": время, "source": "door" \| "relay4"}` или `null` |
| `lock` | замок платы ver_5_1: `{"door": "open" \| "closed" \| null, "powered": true \| false \| null, "control": true \| false}` или `null` |
| `relays[]` | реле, кроме отключённых в настройках |
| `relays[].mode` | `normal` — обычное реле; `lock` — реле 4 управляет замком двери (вкл — закрыта); `wash` — омывание (только `restart`) |
| `relays[].state` | `on`, `off`, `error` или `null` (нет данных) |
| `relays[].power` | `true` — на устройство подаётся электропитание, `false` — питания нет, `null` — неизвестно |
| `relays[].control` | ключу разрешено управлять этим реле |

## Методы

### Список устройств

`GET /api/v1/devices.php`

| Параметр | Значение |
|---|---|
| `ids` | только эти устройства: `1, 3, 5-10` |
| `state` | только в этом состоянии (`online`, `offline`, `never`, `power_off`, `error`, `not_mounted`, `repair`) |
| `mount` | только с этим монтажом: `mounted`, `not_mounted`, `repair` |

Ответ:

```json
{
  "devices": [ {…}, {…} ],
  "summary": {"total": 120, "online": 101, "offline": 6, "never": 2, "bat_low": 1, "power_off": 1, "all_off": 3,
              "not_mounted": 7, "repair": 3},
  "server_time": "2026-11-12T14:36:00+03:00"
}
```

В сводке не смонтированные и демонтированные устройства без связи не входят в `offline`, `never`, `power_off`.

```bash
curl -H "Authorization: Bearer $KEY" "https://relay.example.ru/api/v1/devices.php?state=offline"
```

### Одно устройство

`GET /api/v1/device.php?id=12`

Ответ: `{"device": {…, "last_command": {…} | null}, "server_time": "…"}`. `last_command` — последняя команда
устройству (кроме запроса статуса): `cmd_id`, `command`, `relay`, `status`, `created_at`, `confirmed_at`.

### Команда устройству

`POST /api/v1/command.php` — нужен ключ с правом «Чтение и управление» (кроме `status`).

| Параметр | Значение |
|---|---|
| `id` | номер устройства |
| `command` | `on` — подать питание (включить реле), `off` — снять питание (выключить), `restart` — выключить и через 1 с включить, `status` — запросить состояние, `reboot` — перезагрузить устройство |
| `relay` | `1`–`4` — реле, `5` — замок платы ver_5_1, `0` — все реле (для `on` / `off` / `restart`). Для `status` и `reboot` не нужен |
| `wait` | ждать ответа устройства до N секунд (0–30). По умолчанию 0 — ответ сразу после отправки |

Замок (реле 4 в режиме `lock` или `relay` = 5): `restart` — открыть (кратковременно), `on` — закрыть,
`off` — открыть надолго. Реле в режиме `wash` (омывание) принимает только `restart` («Запуск»).

Ответ: `{"ok": true, "cmd_id": 123456, "status": "sent"}`. `status`:
`pending` — записана, `sent` — отправлена устройству, `success` — устройство выполнило, `error` — устройство
сообщило об ошибке или отправка не удалась.

Если устройство не на связи, команды `on` и `off` сохраняются в брокере и выполнятся при подключении;
`restart`, `status` и `reboot` — нет.

```bash
curl -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"id": 12, "command": "restart", "relay": 2, "wait": 10}' \
     https://relay.example.ru/api/v1/command.php
```

### Состояние команды

`GET /api/v1/command.php?cmd_id=123456`

```json
{"command": {"cmd_id": 123456, "device_id": 12, "command": "restart", "relay": 2, "status": "success",
             "created_at": "2026-11-12T14:36:01+03:00", "confirmed_at": "2026-11-12T14:36:04+03:00"}}
```

### Журнал событий

`GET /api/v1/events.php` — события устройств: связь пропала / восстановилась, изменения реле, команды и ответы,
тревоги АКБ и взлома двери, изменения монтажа.

| Параметр | Значение |
|---|---|
| `id` | одно устройство (без него — все устройства ключа) |
| `after_id` | только события новее этого номера — для опроса изменений |
| `limit` | сколько событий, 1–500 (по умолчанию 100) |

```json
{
  "events": [
    {"id": 90211, "device_id": 12, "at": "2026-11-12T14:36:04+03:00", "type": "relay", "level": "info",
     "message": "реле 2: нет питания → питание подано", "user": null}
  ],
  "last_id": 90211
}
```

`type`: `created`, `online`, `offline`, `relay`, `alarm`, `alarm_clear`, `command`, `reply`, `reboot`, `info`.
`level`: `info`, `success`, `warning`, `error`. `user` — кто отправил команду (`api:имя` — пользователь API).

Без `after_id` события идут от новых к старым, с `after_id` — от старых к новым.
**Опрос изменений:** первый запрос без `after_id`, запомните `last_id`; дальше раз в 10–60 с запрашивайте
`?after_id=<last_id>` и сохраняйте новый `last_id` из ответа.

## Пример на Python

```python
import requests

BASE = "https://relay.example.ru/api/v1"
S = requests.Session()
S.headers["Authorization"] = "Bearer ofs_…"

# устройства без связи
for d in S.get(f"{BASE}/devices.php", params={"state": "offline"}).json()["devices"]:
    print(d["id"], d["name"], d["last_data_at"])

# перезапустить реле 2 устройства 12 и дождаться ответа
r = S.post(f"{BASE}/command.php", json={"id": 12, "command": "restart", "relay": 2, "wait": 10}).json()
print(r["status"])
```

## Безопасность

* Выдавайте каждой системе свой ключ и только нужные устройства; для систем мониторинга — «Только чтение».
* Ограничьте ключ IP-адресами системы, если они постоянные.
* Команды пользователей API записываются в журнал устройства с подписью `api:имя`;
  время и адрес последнего запроса видны в списке «Пользователи API».
